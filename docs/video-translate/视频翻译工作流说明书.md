# 视频翻译工作流说明书

> 当前公开版本、展示名称和发布记录以 GitHub 根目录的 `registry.json` 与 ClawHub 页面为准；本文末尾的版本时间轴只保留历史背景，不作为发布依据。

这是一套用于本地视频高质量中文字幕制作的工作流，目标是用词级时间轴、全文语义审校、专业术语修复和双重质检，把普通机器字幕提升到接近人工字幕的观看效果。

本说明书写给人类使用者和维护者阅读，帮助快速理解这套工作流适合做什么、为什么效果好，以及使用前需要准备什么。AI、WorkBuddy 或自动化流程应阅读英文版执行规则，不要把本中文说明书当作执行规则。

## 使用前需要准备什么

1. 去 OkFile 注册并创建 API Key：`https://www.okfile.com/`。API Key 页面通常在 `https://www.okfile.com/en/account/api-keys`。OkFile 用于把本地音频临时上传成可访问链接，方便阿里 ASR 模型转写。
2. 按阿里官方说明创建百炼 API Key：`https://help.aliyun.com/zh/model-studio/get-api-key`，并从百炼控制台复制工作空间 ID。建议先充值少量余额，用于调用阿里 ASR 模型转写。
3. 准备好 `阿里云 API Key`、`工作空间 ID`、`OkFile API Key`，以及要翻译的视频文件或单视频项目文件夹路径。
4. 把路径复制给 AI，让 AI 使用这个 skill 翻译字幕即可。首次运行会先介绍完整流程与优势，检查本地环境和必备工具，并提示你补充 `.env` 文件中的信息。检查通过后会记录当前用户环境已完成初始化；后续任务跳过首次说明，直接进入任务问卷。

首次独立使用时，AI 必须原样发送固定翻译问卷，不得自行增加“简体、繁体、双语”等选项；上游已经完成同等翻译确认时可以复用答案，只补问缺失或矛盾项。本 Skill 不询问下载质量。ASR 转写完成后，编排模型先通读完整源文，生成领域提示、术语、专名、歧义判断和翻译记忆。初译默认由 `qwen-mt-plus` 通过 `domains`、`terms`、`tm_list` 接收这些上下文；用户也可以选择让当前 Codex / 编排模型直接完成初译。之后编排模型再次通读原文与译文，纠正词义和术语、按语义重分段，再完成确定性 QA 与最终全文 QC。

你只需要准备 3 个核心信息：`DASHSCOPE_API_KEY`、`ALIYUN_WORKSPACE_ID`、`OKFILE_TOKEN`。准备好后写入 `.env`，再把本地视频路径发给 AI 即可。

## 固定转写与双翻译方案

普通用户不需要在大量模型中选择。转写固定为 OkFile + 阿里 ASR 模型；初译只提供两个明确选项，避免临时拼装模型导致不可复现。

当前固定方案：

- 转写模型：阿里 ASR 模型（`ALIYUN_ASR_MODEL`，默认 `qwen-audio-3.1-asr-flash-filetrans`，可回退 `fun-asr`）。它支持长音频和词级时间戳，是字幕时间轴准确的基础；返回结果没有词级时间戳时会直接报错，不会带着没有边界真值的转写继续。
- 默认初译：阿里 `qwen-mt-plus`。稳定、性价比高，实际接收本视频专属领域提示、术语和翻译记忆，缓存也绑定该上下文哈希。
- 可选初译：当前 Codex / 编排模型。它直接翻译分段文件，不需要额外翻译 API Key，但会消耗当前 Agent 的额度；每段输入输出都有哈希回执，可暂停恢复。
- 编排模型：无论初译选哪个，翻译前都先通读完整源文，翻译后再通读原文和全部初译，负责歧义消解、重新翻译、语义分段和最终一致性 QC。

除非用户明确要求重构方案，否则不要临时切换 ASR、helper 或本地模型。

## 如何使用

正常使用时，人不需要手动处理每个脚本。你只需要把本地视频文件或只含一个待翻译视频的专用项目文件夹交给 Codex 或其他支持该 skill 的自动化工具，并在任务开始前确认几个问题：

> 简单说：把本地视频路径发给 AI，回答几个确认问题，剩下由 AI 跑流程。命令行是 AI 的后台执行方式，不是普通用户必须记住的使用方式。

- 源语言是否默认英文，是否需要改成法语、西班牙语或意大利语。
- 目标语言是否保持中文。当前默认目标语言为中文，内置术语库、排版和质检规则也主要围绕中文字幕优化；如果要稳定翻译成英文、法语、西班牙语、意大利语等目标语言，需要补充对应目标语言的提示词、术语库和质检规则。
- 初译是否使用默认的 `qwen-mt-plus`，还是由当前 Codex / 编排模型直接翻译。默认 Qwen 更稳定省额度；Codex 模式适合追求更高质量并愿意消耗当前 Agent 额度的任务。
- 视频画面里是否有大量文字、PPT、图表、软件界面、代码、指标名，或有意义但旁白没有完整讲出来的图片信息。
- 是否启用 OCR/屏幕上下文辅助。默认不启用；只有画面文字确实影响理解时才建议启用，因为它会增加处理时间和成本。
- 字幕导出路径是否使用视频所在的专用项目文件夹。如果要导出到其他位置，直接提供新的文件夹路径即可。

收到路径后，AI 会先运行本地确定性素材检查，检查项目根目录和标准 `.work/input/` 交接目录，而不是只查看文件夹第一层。检查结果会明确列出选中的视频、可复用音频、原语言 SRT/VTT，以及没有音频时需要从视频提取的状态。WebM 同时可能是视频或纯音频容器，因此会通过 `ffprobe` 读取实际媒体流，不会只凭扩展名判断。

输出标题通常不需要用户另选。AI 会从所选视频文件名或项目目录提取真实标题，去掉开头日期、结尾平台唯一编码、扩展名和发布版后缀；如果原题是外文，则参考视频领域术语翻译为中文。文件夹内没有视频时停止；有多个视频时列出候选并请用户明确选择。只有存在多个可能的源视频或标题时才询问用户。

流程完成后，AI 会在对话框里返回本次任务摘要，包括输出文件、总耗时、各环节耗时、转写模型、翻译模型、编排模型、QA warning 概况等。随后会输出两类字幕文件：

- ASS：推荐观看格式，能按视频显示尺寸固定中英文字号、位置和样式；横版、竖版和方形视频自动使用对应布局。
- SRT：通用兼容格式，适合上传平台或备用。

成功交付后，专用项目文件夹和原视频统一使用中文净标题，ASS/SRT 也使用同一标题并加上字幕标识。例如项目目录为 `1亿+美元交易者：他最好的交易策略（市场奇才）/`，视频为 `1亿+美元交易者：他最好的交易策略（市场奇才）.mp4`，字幕为 `1亿+美元交易者：他最好的交易策略（市场奇才）.中英双语字幕.ass/.srt`。工作流不会覆盖已存在的视频或项目目录，也不能退化为“原版视频”“视频”等通用名称。

## 长视频处理时的状态反馈

如果视频超过 10 分钟，AI 在开始前应先告诉你：视频大约多长、预计首轮处理大概需要多久、以及每 10 分钟会反馈一次状态。这个预计只能给范围，不能保证精确，因为上传速度、阿里排队、AI 模型速度、是否启用屏幕上下文、是否需要 QA 修复都会影响耗时。

长任务执行中，AI 不应该长时间沉默，也不应该说“等通知”然后结束当前轮次。WorkBuddy 这类平台的通知可能不会自动唤醒 agent，所以正确做法是让任务在前台持续执行，或在同一轮次里循环读取任务状态直到完成、暂停或失败。每 10 分钟至少应反馈一次：

- 已完成哪些环节。
- 当前正在执行什么环节。
- 是否正在复用缓存。
- 如果能判断，粗略还剩多久。

每个任务结束后，运行摘要会记录实际耗时。后续处理同类视频时，应参考这些历史耗时，让预估逐渐更接近真实情况。

## 常见使用场景

以下场景可以直接使用这套工作流：

- 课程、培训、讲解视频：适合把英文或小语种视频做成自然的中文字幕。
- 金融交易、投资、期权、订单流视频：内置术语库对这类内容最友好，能避免明显教材腔或错译。
- 访谈、播客、分享、市场复盘：如果主要信息来自人声，通常不需要启用 OCR/屏幕上下文。
- 录屏课程、软件教程、PPT 讲解：如果屏幕文字、图表、按钮、代码或指标名会影响理解，建议启用屏幕上下文。
- 批量视频：适合按批次处理，但建议先抽查 1-2 个成品，确认术语和字幕节奏符合预期后再继续批量跑。
- 非金融领域视频：可以使用同一流程，但应维护对应领域的术语库、专名和表达风格。

以下场景可以处理，但需要降低自动化预期：

- 音频噪声很大、强口音明显、多人同时说话的视频。
- 画面信息很重要，但用户不愿启用屏幕上下文的视频。
- 需要翻译成非中文目标语言的视频。当前流程架构可以扩展，但默认内置规则仍以中文字幕为主。

## 这套工作流做什么

这套工作流用于把本地视频快速制作成自然、专业、接近人工字幕质量的中文字幕。它不是简单把字幕丢给 AI 翻译，而是把“听写识别、语义分段、专业翻译、时间轴匹配、排版和质检”拆成一套完整流程。

它特别适合课程、培训、讲解、分享、访谈、市场复盘、软件教学等内容。目前主要用于金融交易类视频，因此内置术语库也优先服务交易、投资、订单流、期权和市场分析等内容。

## 工作流概述

整体流程可以概括为：

```text
视频/项目目录素材发现 -> 复用音频或 FFmpeg 临时提取 -> OkFile + 阿里 ASR 词级转写 -> 原字幕词文校对（如有） -> 编排模型译前全文源文分析 -> qwen-mt-plus 或当前 Agent 初译 -> 编排模型全文重译审校与语义分段 -> 确定性 QA -> 最终全文 QC -> 导出 ASS/SRT -> 项目、原视频和字幕统一中文命名
```

可选 OCR/屏幕上下文只作为补充信息使用，不替代语音转写和词级时间轴。它适合用于 PPT、图表、软件界面、代码演示、屏幕文字较多的视频。普通口播或画面文字不重要的视频，不建议启用。

## 为什么效果更好

普通字幕工具通常直接依赖转写模型的原始断句。原始断句经常不符合中文观看习惯，也容易出现长句堆叠、断点奇怪、术语生硬和中英文不匹配的问题。

这套工作流的关键差异是：不直接相信机器原始断句，而是让 AI 基于完整上下文重新分段和翻译，再用词级时间戳回填时间轴。这样字幕会更像人工处理过的结果，而不是机器转写的副产品。

## 核心优势

- 词级时间戳对齐，说话节奏和字幕显示更自然。
- AI 语义分段，减少机器断句带来的生硬感。
- 中文表达优先按观看体验处理，而不是逐词硬翻。
- 可维护术语库，让不同领域的译法逐渐稳定。
- 支持 ASS 样式控制，中文更清楚，源语言辅助展示。
- 自动识别视频显示方向和旋转信息。竖版使用 `1080×1920`、中文 `64px`、英文 `34px`、描边 `3px`、阴影 `1px`、左右边距 `80px`，字幕块顶部固定在距底边 `550px` 的位置；长短字幕不再因底部对齐而上下跳动。
- 可选屏幕上下文辅助，帮助理解 PPT、图表、软件界面和屏幕文字。
- 最终带质检流程，尽量减少漏词、长句、闪字幕、孤立碎片和术语错误。
- 不需要下载本地大模型，转写速度更快，也更节省本地硬盘和算力。

## 适合什么视频

当前最适合：

- 英文课程和培训视频。
- 金融交易、投资、订单流、价格行为、期权、宏观市场类讲解。
- 录屏课程、webinar、软件平台教学。
- 访谈、分享、市场复盘、策略讲解。

也可以处理少量常见小语种视频：

- 法语
- 西班牙语
- 意大利语

这套流程不局限于金融交易。如果长期用于电影、法律、医学、游戏、产品教程等场景，只要持续维护对应领域的术语库和表达风格，也可以逐渐适配其他内容类型。

## 流程能力边界

- 当前服务录制好的本地视频，不做实时字幕或直播同传。
- 当前导出 ASS/SRT 字幕文件，不负责把字幕硬压进视频。
- 当前默认目标语言为中文，内置流程、术语库、热词库和质检规则都优先围绕“翻译成中文”优化。
- 工作流架构可以扩展到英文、法语、西班牙语、意大利语等目标语言，但需要为目标语言补充提示词、术语库、排版和质检规则，不能直接假设和中文路线一样成熟。
- 当前生产主线固定为 OkFile + 阿里 ASR 模型。
- OCR/屏幕上下文默认关闭，只在视觉信息确实重要时启用。
- 如果没有可靠的词级时间戳，字幕时间轴质量会明显下降。
- 如果术语库不维护，跨领域翻译质量会下降。
- 低质量音频、强口音、多人重叠对话、背景噪声很大的视频，转写识别准确性会显著降低，仍建议人工抽查。

## 需要的本地环境和工具

本地需要：

- Python 3.9 或更高版本。
- `ffmpeg`，用于从视频里提取音频，也用于可选截图。
- `ffprobe`，用于读取媒体流并区分视频型 WebM 与音频型 WebM。
- 可访问 OkFile 和阿里百炼 / DashScope 的网络。
- 足够的本地空间，用于临时音频、转写结果、提示词、字幕文件和质检报告。

第一次在新设备和当前用户环境中运行时，AI 会先展示一次流程和优势说明，再检查这些环境和工具。如果缺少 `ffmpeg` 等工具，AI 会提示安装方式，或在需要时请求你的授权后再安装。检查通过后会写入不含密钥的本地初始化记录；后续同一环境直接进入任务问卷，但正式外发前仍会做轻量环境校验。

## 为什么选择阿里 ASR 模型

这套流程选择阿里 ASR 模型（当前默认为 `qwen-audio-3.1-asr-flash-filetrans`），主要因为它适合长录音转写，支持异步 API，并能返回词级时间戳。词级时间戳是整套工作流的关键，因为后续所有字幕分段都要精确匹配回真实语音时间。

该模型系列支持热词：预编译热词列表绑定 `target_model` 且无法改绑，模型不一致时不会报错但热词静默失效；即时热词仅 Qwen-Audio-3.x 支持，随请求内联传入，没有绑定问题。两者都适合提升人名、品牌名、指标名、平台名和专业术语的识别效果。

当前参考价格约为：

- `0.00022 元/秒`
- `0.0132 元/分钟`
- `0.792 元/小时`

实际价格和免费额度可能变化，批量处理前应以阿里百炼官方价格页为准。

## 为什么选择 OkFile

阿里 ASR 需要访问在线音频 URL，而源视频通常在本地电脑上。OkFile 的作用是把本地提取出的音频临时上传成可访问链接，再交给阿里 ASR 模型转写。

选择 OkFile 的原因是轻量、注册方便、能通过 API 上传文件并生成 URL。对这套工作流来说，它比自行配置 OSS、签名 URL 或云存储权限更简单。

## 为什么不使用本地大模型

本地跑 Whisper 等大模型会占用硬盘、CPU/GPU 和较长时间。对视频字幕工作流来说，本地电脑更适合做轻量任务：提取音频、组织文件、匹配时间轴、生成字幕和质检。

真正耗时的转写交给云端 API，整体更快，也不影响电脑继续做其他工作。

## 为什么术语库重要

字幕质量很大程度取决于术语库。尤其是金融交易视频，如果术语翻译不地道，即使句子语法正确，观看体验也会很差。

例如：

- `order flow` 应译成“订单流”。
- `price action` 应译成“价格行为”。
- `scalper` 在交易语境里不是“黄牛”，固定使用“剥头皮交易者”；只有原文明确表达 short-term trading 时才使用“短周期交易”或“超短线交易”。
- `fair value gap` 更适合按交易圈常用说法译为 “FVG / 公平价值缺口”。

如果换到电影、法律、医学、游戏或产品教程，也应维护对应领域的术语、专名和表达习惯。

## 热词和专名需要持续维护

ASR 再好，也可能把专名、品牌名、人名、指标名拆错或识别错。例如交易平台、课程品牌、指标名称、人名和缩写，经常需要人工沉淀为固定规则。

维护时要先判断问题发生在哪一层：如果英文原文一开始就被听错、拆词或把人名品牌名识别错，这是 ASR 热词问题；如果英文已经听对，只是中文翻译不地道，这是术语库或质检规则问题。不要把所有翻译偏好都塞进 ASR 热词库。

建议每处理 3-5 个同领域视频，或一次大批量视频结束后，集中检查一次常见问题。反复出现的专名、平台名、指标名、ticker 和高价值短语，可以维护到阿里的热词表里；中文译法、字幕风格和句子节奏，则维护到术语库、修复规则和质检规则里。

## 后续维护重点

后续最重要的不是频繁更换模型，而是持续维护：

- 常见术语的标准译法。
- 人名、品牌名、平台名、指标名。
- ASR 经常拆错或识别错的词。
- 不同领域的表达风格。
- 正式交付前的质检规则。

只要这些内容持续积累，这套工作流会越来越接近对应领域的专业人工字幕效果。

## 常见问题 FAQ

### 我需要自己记命令吗？

不需要。把本地视频文件或单视频项目文件夹路径交给 AI，回答源语言、目标语言和是否启用屏幕上下文等确认问题即可。命令行是 AI 在后台执行流程的方式。

### 为什么流程中途会停下来？

脚本使用专用退出码把控制权交回当前 AI：`3` 是译前全文源文分析；Codex 原生翻译模式额外使用 `4` 完成分段初译；`5` 是译后全文重译审校；`6` 是最终全文 QC。这些是 Agent 内部工作门禁，不需要用户处理；Agent 必须在同一任务轮次中完成门禁，并用同一任务 ID 和同一个翻译模式续跑。退出码 `3`–`6` 或状态 `waiting` / `running` 都表示运行尚未完成，不能导出或覆盖成品。

### 原语言字幕会改变时间轴吗？

不会。阿里 ASR 的词和词级时间戳是唯一边界真值。参考 SRT/VTT 必须先满足时间重叠，再按当前 ASR 词跨度裁掉前后借词；只有文本相似时才能校正当前段的 `SRC_DISPLAY`。如果多数映射异常，整份参考字幕会自动停用并回退 ASR 词流。

### 怎样防止中文连续错位？

初译阶段每个 `ZH_i` 只能翻译同一 SEG；残句保留对应残句，不把完整中文拆给多段。语义复核和最终 QC 都必须把每条中文与自己的源文及前后至少两段比较；若中文更匹配相邻段，或连续多条出现同方向偏移，直接判为 blocker，修正后才能继续。

### 什么状态才允许正式导出？

必须同时存在且通过当前哈希校验：源文分析、Agent 初译（如使用）、语义复核、确定性 QA、最终全文 QC；`final_qa_report.md` 必须记录 `Blockers: 0`。底层导出脚本也会执行这套检查，不能从未完成的 `segments.txt` 手工生成 ASS/SRT；本公开 Skill 不生成 BCC。

### 为什么本地视频不会再叫“原版视频”？

工作流会先检查原视频文件名和专用项目目录，优先使用已有的真实中文标题；外文标题则由 Agent 结合领域术语翻译成中文。日期、平台唯一编码、扩展名和发布版后缀会被去掉，结果写入当前运行的命名回执。所有门禁通过后，项目文件夹、原视频、ASS 和 SRT 一起改为该中文净标题，并记录最终路径，所以不能再手工换成“原版视频”等占位名。

### 横版和竖版字幕会用同一套参数吗？

不会。脚本会读取第一条视频流的显示尺寸和旋转元数据，默认自动选择横版、竖版或方形布局，并把结果锁定到本次运行。横版保持原有参数；竖版 ASS 使用 `1080×1920` 画布、中文 `64px`、英文 `34px`、描边 `3px`、阴影 `1px`、左右边距 `80px`。竖版字幕块采用顶部居中锚点，顶部固定在 `Y=1370`，即距 1920px 画面底边 550px；后续换行向下延展，不会因字幕行数变化而上下漂移。只有视频旋转元数据明显错误时，才由 Agent 使用 `--subtitle-layout landscape|portrait|square` 覆盖，不能在同一运行中途切换。

### 什么时候需要启用 OCR/屏幕上下文？

只有当 PPT、图表、软件界面、代码、指标名或画面文字会影响理解时才建议启用。普通口播、访谈、播客、画面文字不重要的视频，建议关闭。

### QA 没通过是不是要我手动改？

不是优先让用户手动改。AI 应先根据 `final_qa_prompt.txt` 和 `final_qa_report.md` 自动修复，再重新导出。只有连续修复失败，或需要专业判断时，才应询问用户。

### 支持实时字幕或直播同传吗？

不支持。当前工作流只接受录制好的本地视频文件；用户直接提供音频时会拒绝。素材准备组合流程中的隐藏音频仅作为内部转写优化使用，不属于用户输入。

### 支持把字幕硬压进视频吗？

不支持。当前输出 ASS/SRT 字幕文件。硬压视频属于后续独立步骤。

### 支持翻译成中文以外的目标语言吗？

架构可以扩展，但当前内置提示词、术语库、排版和质检规则主要围绕中文字幕优化。如果要稳定翻译成英文、法语、西班牙语、意大利语等目标语言，需要补充对应目标语言的规则。

### 音频质量很差会怎样？

低质量音频、强口音、多人重叠对话和背景噪声会明显降低转写准确性。重要内容建议人工抽查。

### 长视频为什么一直没消息？

不应该一直没消息。超过 10 分钟的任务，AI 应提前说明预计耗时，并每 10 分钟汇报一次当前状态。如果长时间没有反馈，可以让 AI 读取本次运行目录里的 `workflow_status.json`，说明当前卡在哪个环节。

### 长视频分段翻译很慢怎么办？

长视频默认由 `qwen-mt-plus` 串行初译并支持上下文绑定缓存；选择 Codex 翻译时按哈希绑定的章节逐段完成并保存。Agent 不得把任务丢到后台后说“收到通知会继续”：通知不会自动唤醒已经结束的模型轮次。正确做法是保持前台进程，或持续轮询同一个运行 session，内部至少每分钟检查一次，并按约定每 10 分钟向用户反馈状态。

## 不适合的用法 / 反模式

- 不需要自己记命令。把视频路径交给 AI 即可，命令行只是 AI 在后台执行流程的方式。
- 不要默认启用 OCR/屏幕上下文。只有 PPT、图表、软件界面或屏幕文字会影响理解时才启用，否则会增加耗时和成本。
- 不要把低质量音频当成完全自动化任务。强噪声、强口音、多人重叠对话会影响转写准确性，重要内容应抽查。
- 不要随意切换 ASR 模型。当前流程围绕 OkFile + 阿里 ASR 的词级时间戳设计，换模型需要重新验证时间戳和对齐效果。
- 不要把 QA blocker 直接丢给用户手动修。AI 应先根据 `final_qa_prompt.txt` 自动修复，连续失败或需要专业判断时再请用户确认。
- 不要把字幕硬压进视频。本工作流交付 ASS/SRT 字幕文件，硬压视频属于后续独立步骤。
- 不要让长视频任务长时间无反馈。超过 10 分钟的任务，应每 10 分钟报告一次状态。
- 不要临时手写并发翻译脚本。默认 Qwen 路径使用内置串行缓存；Codex 路径使用内置 Agent 翻译闸门和哈希回执，两者都必须按正式流程续跑。
- 不要直接调用底层导出脚本绕过门禁，也不要把退出码 `3`–`6` 的中间产物当作成品。

## 字幕效果示例

```text
原文：Now, this process is very important, because once you have simulated how much money you can make into the year...
字幕：这个过程至关重要：一旦你模拟出全年潜在收益，再每天实盘交易，情绪干扰就会大幅降低
```

好的字幕不是逐词硬翻，而是在不偏离原意的前提下，让中文自然、信息密度合适、显示节奏舒服。

本版本修复参考字幕跨 Fun-ASR 段污染与未完成运行可被手工导出的缺口：参考 SRT/VTT 只能校正当前 ASR 词跨度，异常时整份停用；Agent 初译、语义复核和最终 QC 增加同 SEG 与相邻窗口错位检查；全段无修改的语义回执必须明确确认；底层导出同时核验全部 validated 证据、当前文件哈希、`Blockers: 0` 和工作流状态，并加入固定内容抽查。

### v1.7.0（2026-07-29）

本版本统一本地视频与下载视频的可见文件命名：从原视频文件或项目目录提取真实标题，去除开头日期、结尾平台编码和扩展名，并按领域术语翻译成中文；运行会把中文净标题写入命名回执，底层导出拒绝“原版视频”等占位名或临时改名。当时配套的公开 Flow 增加了输入类型路由；该 Flow 后续已停止使用并从公开仓库删除。

### v1.8.0（2026-08-02）

本版本加入本机首次使用状态：首次显示流程、优势和凭据准备说明，环境检查通过后后续任务直接进入固定问卷。输入同时支持本地视频文件和单视频项目文件夹；文件夹多视频时必须明确选择，并会在项目目录与 `.work/input/` 中发现匹配音频和原语言 SRT/VTT。全部翻译与质检门禁通过后，专用项目文件夹、原视频、ASS 和 SRT 统一为同一个中文净标题；共享目录、多视频目录和既有目标一律拒绝自动覆盖。

### v1.8.1（2026-08-02）

本版本修复 `.work/input/` 中音频型 WebM 被误当作视频容器、从而没有复用既有 ASR 校对音频的问题。新增无外发、无模型调用的 `--inspect-inputs` 确定性检查入口；Agent 必须用它检查项目根目录和标准交接目录，不能再用只查看顶层的临时命令代替。环境检查同步要求 `ffprobe`，并补充音频型与视频型 WebM 的媒体流识别测试。

### v1.9.0（2026-08-02）

本版本新增按显示尺寸和旋转元数据自动选择的横版、竖版、方形字幕布局，并把布局记录纳入 QA 与导出门禁。横版输出保持原有视觉参数；竖版使用 `1080×1920` 画布、中文 `64px`、英文 `34px`、描边 `3px`、阴影 `1px`、左右边距 `80px`，字幕块顶部固定在 `Y=1370`（距底边 550px）。中英文换行使用同一份布局记录，竖版 QA 会阻止超出三行的源语言字幕，避免长短字幕位置漂移或文本溢出。

### v1.9.1（2026-08-02）

本版本精简任务问卷的路径与文件命名说明。用户已经提供路径时，Agent 先执行确定性输入解析，问卷直接显示已识别的视频，不再重复索取路径；用户未提供路径时，仅简短请求本地视频文件或存有视频的文件夹路径。

### v1.9.2（2026-08-02）

本版本修复已完成运行在项目和视频改为中文路径后无法受控重新最终化的问题。只有交付清单精确证明当前视频是同一个已重命名交付物，且重新探测的尺寸、旋转和字幕配置全部不变时，才允许布局记录同步到新媒体路径；几何或配置变化仍会被门禁拒绝。

### v1.9.3（2026-08-02）

本版本修复正式字幕、中文文件名和运行摘要均已成功交付后，工作流总状态仍停留在 `running` 的诊断错误。正常运行与既有运行重新最终化现在都会在全部交付步骤成功后把总状态标记为 `done`；等待 Agent 门禁、异常或部分完成时仍保持 `running`，不会把中间产物误报为正式成品。

### v1.9.4（2026-08-02）

本版本明确横版、竖版和方形字幕参数都是已经校准的固定生产 profile，不是每个视频都要重新测试的选项。普通任务在自动识别显示方向后直接套用对应参数，不生成布局预览、不要求人工确认，也不重新调整字号、位置、边距、描边、阴影或换行阈值；只有用户明确要求，或媒体几何与布局证据异常时才生成诊断预览。
